# v0.5 plan: Training modes I

## Context
v0.4 (Stockfish) was signed off and merged on 2026-11-02. v0.5 adds the first new ways to train beyond Standard:
- **Commit the line** (FR-4.2): an opt-in calculation drill. You enter the whole line, both sides, then Submit.
- **Spaced repetition** (FR-4.6): your misses come back on a Leitner schedule.
- **Depth ladder** (FR-4.5): now an **Order** option rather than a mode (Adam's decision).
- A **Modes** control in the left (filters) panel.

Work happens on branch `v0.5` from `main`. This plan is saved as `plans/v0.5.md` in the first commit and ticked off as items land.

**Requirement IDs in scope:** FR-4.2, FR-4.5 (reworded), FR-4.6, FR-3.11 (the new order), §3.2 (mode selector), FR-9.1 "per mode" (unbuilt until now: Stats groups by mode now that there's more than one), FR-5.1–5.5 applied to the new mode, §8.3 (angle when the length is known in advance).

**Out of scope, for later versions:**
- Name the idea first, Danger spotting, and mistake reasons: v0.6. They don't appear in the selector, not even greyed out.
- Commit-mode calculation accuracy *on the Stats page* (FR-9.3): v0.6. v0.5 stores it on each attempt and shows it on the result panel.
- My-games puzzles in SRS: v0.8.

## Decisions from Adam (planning, 2026-11-02). REQUIREMENTS.md, ROADMAP.md and ARCHITECTURE.md §4 change in the first commit to match
1. **Commit the line stays in v0.5 as an opt-in mode.** Standard stays the default and is unchanged.
2. **Modes control in the left panel**: a segmented control at the top of the filters panel: *Standard* / *Commit the line* / *Spaced repetition*.
   - The last mode you used is saved through the bridge (`trainer.mode`). A fresh install starts on Standard.
   - **Switching mode while a session is running starts a new session** in that mode, with the current filters and Rated toggle. It's the same as pressing Start, and the puzzle in progress is handled exactly as Start handles it today (pinned by a test).
3. **Commit the line: the length is hidden by default**, with a **Show move count** switch shown only in this mode and saved as `commit.show_length`.
   - When it's on, you see "Find N moves" and the board stops taking moves at the solution's length.
   - Because you then know the length in advance, the angle becomes the length theme when the themes are All (§8.3). If a theme matched, the angle is still that theme. The switch's description says so.
4. **Spaced repetition takes every miss, past misses included.**
   - A loss in any mode puts the puzzle in box 1. Losses from v0.1–v0.4 are included, so your first SRS session may have a backlog.
   - Only wins **in Spaced-repetition mode** move a puzzle up a box. A win from the last box graduates it, so it's no longer scheduled.
   - A later loss in any mode sends it back to box 1, even after it graduated.
5. **Fast-forward time: `--dev` runs only.** Settings → Debug → "Fast-forward: +N days" moves the whole app's clock (due dates and new attempts' timestamps). A banner shows while it's on. The bridge refuses it outside `--dev`.
6. **Depth ladder is an Order option**: Order = Random / Easy → hard / Grouped by theme / **Depth ladder**, available in Standard and Commit the line.
7. **Ladder level: saved per theme set, never drops** (my default, since the question was reframed; say so if you want otherwise). See design 3.
8. **Collapsible filters panel (new, FR-1.14).** A **Hide filters** button (chevron) at the top of the left panel collapses it, so the panel stays out of the way while you play.
   - **Collapsed:** a slim strip with **Show filters**, the mode, a one-line summary (for example "Fork, Pin · 1200–1800 · 2,431 puzzles") and the Rated state. The trainer column widens to use the space.
   - **Expanding** brings back the full panel unchanged. Nothing is lost or reset.
   - The state is saved through the bridge (`ui.filters_collapsed`, never browser storage), so it survives a relaunch. The default is expanded.
   - It doesn't collapse by itself when you press Start. A keyboard shortcut (`F`) toggles it and is listed in the shortcuts help.

## Design (each item gets an ARCHITECTURE §7 entry)

### 1. Modes, the protocol and the session
- `core/modes/base.py`: `HelpResult`/`Feedback` unchanged. Add `CommitResult` (one grade per ply, the attempt, `replies_correct`, `replies_total`).
- **`core/modes/commit_line.py` `CommitLineMode`**:
  - It has `start`, `start_practice`, `on_help`, `give_up`, plus `on_submit(state, line, now_ms) -> CommitResult`. Its `on_move` raises `ConflictError`, since nothing is checked move by move.
  - This deviates from ARCHITECTURE §3 decision 6 ("plugs in without changing the trainer view"), and the §7 entry records it: Commit needs its own entry UI.
- **Spaced repetition reuses `StandardMode`'s move rules.** It's recorded with mode `spaced_repetition`, so only its queue and its box effects differ. No new mode class is needed.
- `SessionService`:
  - picks the mode from a registry keyed by name
  - records `mode.name` on the session and on each attempt
  - `_Current.state` becomes `StandardState | CommitState`
  - adds `submit_line(session_id, moves)`
  - routes the queue: SRS sessions draw due puzzles; the others draw from the filters, with the ladder when Order = Depth ladder
  - keeps the existing guards: practice runs record nothing, and FR-7.3 (engine only after the end)

### 2. Commit the line (FR-4.2)
- **Entry (front end):** chess.js checks legality only. You move **both sides** with no feedback and no automatic replies. Controls: **Undo**, **Clear**, **Submit**.
  - With Show move count on: "Find N moves" and the entry stops at N plies.
  - Hidden (the default): no cap beyond a sanity limit of 2× the solution plus 10 plies, at most 60.
- **Backend validation:** python-chess re-checks the line's legality, so an illegal or overlong line gets a `ValidationError`.
- **Grading** (pure, unit-tested):
  - Your moves are compared with the solution's by index.
  - Where every earlier ply matched exactly (so it's the same position), a mating move is accepted where the solution mates, and the line ends there.
  - Missing player moves are wrong, and extra plies after the solution are ignored.
  - **Win** = every player move matches and no help was used before Submit (FR-5.1, 5.2).
  - **Calculation accuracy** = predicted replies that match ÷ the solution's replies. Missing ones count as not predicted. It's separate from the win.
  - `first_move_correct`, `line_correct` and `time_ms` (from start to Submit) are recorded as usual.
  - `first_wrong` (for Stockfish's refutation) is set only if every ply before your first wrong move matched, so the position is real. Otherwise there's no refutation section.
- **Help:**
  - Before Submit, **Hint** circles the piece that makes the *first* player move, and **Show answer** (after Hint, as in Standard) ends the puzzle. Both are losses.
  - After Submit, everything is free (FR-5.4).
  - **Try again** works (`start_practice`).
- **Result panel:** your line with ✓/✗ on each ply (yours and the predicted replies), "Replies predicted: 2 of 3", then the usual themes, rating change, Show answer, engine panel and Analyze.
- **Storage (migration `0004_modes.sql`):** two nullable columns, `attempts.replies_correct` and `attempts.replies_total`.

### 3. Depth ladder as an Order (FR-4.5, FR-3.11)
- `FilterSpec.order` gains `"depth_ladder"`.
  - Levels: **short (2 moves) → long (3) → very long (4+)**, which are `lengths` 2, 3 and 4.
  - While it's on, the Number-of-moves control is disabled ("set by the ladder"), and **ratios can't be combined with it**: validation says so and the UI disables it.
- **Ladder key** = the theme set: sorted themes + match mode + excluded themes. All themes is a valid set.
- **Level from the log** (ARCHITECTURE §3 decision 4, with no separate store):
  - Migration 0004 adds `attempts.ladder_key` and `attempts.ladder_level`.
  - Current level = the highest `ladder_level` recorded for the key, then moved up one if the last *window* attempts at that level reach the *threshold*.
  - It never drops, and practice runs never count.
  - `core/ladder.py` holds the pure rules.
- **Settings:** threshold (default 80%) and window (default 20) in the gear settings, saved as `ladder.threshold` and `ladder.window`, with validation.
- **Session:**
  - Each refill draws from the current level, in random order.
  - On a level-up, the session drops its queued keys and refills from the new level. A fixed queue size still counts all puzzles.
  - The session bar shows "Ladder: Long (2/3) · 14 of 20 · 79%" and a short "Level up!" notice.
- **Angle:** the ladder fixes the length, so `lengths` isn't All. The existing rule then reports the matched theme, or the length theme when the themes are All. That's truthful because you know the length.

### 4. Spaced repetition (FR-4.6)
- **`core/srs.py`** (pure): `schedule(events, intervals, local_date) -> Card | None` replays one puzzle's attempts in order.
  - A loss means box 1, due one interval later.
  - An SRS-mode win while in a box moves it up a box.
  - A win from the last box graduates it.
  - Other wins change nothing.
  - No loss means the puzzle isn't in SRS.
- **Due by local calendar day:** a miss at 9 pm is due the next morning, not at 9 pm. `Clock` gains `local_date(dt)` (`SystemClock` uses the OS timezone; `FixedClock` has a fixed offset).
- **Intervals:** default 1, 3, 7, 14, 30 days, editable in the gear settings (`srs.intervals`): 2–10 boxes, strictly increasing, 1–365 days each.
- **Repo:** one query returns the attempts (finished_at, mode, win) of every puzzle that has a loss, using the existing `attempts_puzzle_win` index. The service builds the cards.
- **SRS session:**
  - The queue = due Lichess puzzles, most overdue first. **The filters don't apply**, so the mixer greys them out and shows "N due now · next: Tue 4 Nov".
  - With nothing due, Start is disabled with that message.
  - Queue size still applies.
  - Angle = `mix`, since no theme or length was chosen.
  - The Rated toggle still applies. The existing "Already played: rating unaffected" badge shows (FR-4.6).
  - Puzzles a re-import removed are skipped (FR-2.4).
- **Fast-forward (dev):** `adapters/system_clock.py` gets an `OffsetClock(SystemClock, days)`, wired in `app.py` only when `--dev` is on. The offset is saved in `debug.time_offset_days` and can be changed live. `monotonic_ms` is unaffected.

### 5. Bridge, settings, Stats
- **New bridge methods** (allowlist test updated in the same commit): `submit_line`, `get_srs_status`, `get_ladder_status(spec)`, `set_time_offset` (refused outside `--dev`).
  - `start_session(spec, rated, mode)` gains `mode`, with a default of `"standard"` so older calls still work.
  - `set_setting` accepts the new keys through validators: `trainer.mode`, `commit.show_length`, `ladder.threshold`, `ladder.window`, `srs.intervals`.
  - `dto.py`/`types.ts` regenerated (`scripts/gen_types.py`). `mockClient` implements everything.
- **Stats (FR-9.1):** a **By mode** table (Standard / Commit the line / Spaced repetition) next to the existing theme, length and rating-band tables.

### 6. Front end
- `MixerView`:
  - the Modes control
  - the Order option
  - the SRS due line, with the filters greyed out in SRS
  - Show move count (Commit only)
  - the ladder status line under Order
- `TrainerView`: a Commit entry/submit branch, with the graded-line result in a new `components/CommitLine.tsx`. The SRS and ladder badges sit in `SessionBar`.
- `SettingsModal`: Training (ladder threshold and window, SRS intervals) and, only in `--dev`, Debug (fast-forward).
- App: a "Time fast-forwarded +N days (dev)" banner.
- **Collapsible filters (FR-1.14):** `App.tsx`'s grid switches the left column between the full `MixerView` (md=4) and a `FiltersStrip` component (summary + Show filters, the trainer at md=11). `MixerView` stays mounted while hidden, so its state survives. `ui.filters_collapsed` goes through `UiSettings` and `set_setting` with a bool validator. The `F` shortcut is added to `state/shortcuts.ts` and `ShortcutsHelp`.
