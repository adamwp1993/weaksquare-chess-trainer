## What exploration found (these shape the design)
- **pywebview doesn't isolate a second window.** `platforms/edgechromium.py` turns on `IsWebMessageEnabled` and injects the pywebview JS bridge into **every** window on `NavigationCompleted`, even one with no `js_api`. Messages go to `js_bridge_call` for that window. A Lichess window in the app's own process would still reach pywebview's internals, so it runs as a **separate child process** (step 0).
- **Real studies are untidy.**
  - `swkkeUJZ`: 39 chapters, emoji titles, 254 arrows, and 4 text-only chapters on invalid positions (an empty board, pawn art with no kings).
  - `nq1GGbNO`: 33 chapters, and **31 are normal (non-gamebook) chapters**, with up to 120 side moves nested several deep. One chapter starts from a custom FEN, and one chapter title contains a URL.
  - `ZCPaIb70`: 8 clean gamebook chapters, one with a custom FEN.
  - Every move in all three passes python-chess.
- **Normal chapters are the main case,** not gamebooks, so the move list with nested branches is the core screen.
- **Side lines mix two things:** the opponent's alternatives and the author's "what if White played…" analysis. Adding all of them to a repertoire would put several moves for your side on one position, so Add to my repertoire takes the main line by default.
- **Links can name a chapter:** `lichess.org/study/{id}/{chapterId}`. The export has a `ChapterURL` header that maps chapter IDs.
- **Private studies return 403 when signed out.** The app's scopes are `puzzle:read puzzle:write` (`core/oauth.py`), so it can't read them today.
- **`/api/study/by/{username}`** returned only id, name, createdAt and updatedAt when checked on 2026-11-06.

## Step 0: Lichess window isolation (FR-13.3 gate)
**Result: isolation proven (2026-11-07).** The window stays in v0.14. `tests/smoke/test_lichess_window_isolation.py` (8 tests, real window) plus 3 unit test files pass.
- [x] Spike: `weaksquare.lichess_window` runs as a child process launched by `adapters/lichess_window.py`.
  - Its own temporary WebView2 profile, deleted on close after waiting for the browser process; no `js_api`.
  - pywebview couldn't be stripped far enough (it injects its bridge on every navigation), so the window uses the **WebView2 control directly** through pythonnet, with the assemblies pywebview ships. No new dependency.

  - navigation and popup tests show it can't leave Lichess
  - inherited debugging port ignored; profile deleted; closing the pipe closes the window

## v0.14c: Game Review in three parts (new FR-11.36)
- [x] `core/game_review.py` `game_story()` (no I/O):
  - **Summary:** result, accuracy and ACPL, turning point (largest swing), a verdict per phase
  - **What you did well:** each item is engine-backed:
    - only move found: best move, with the 2nd line ≥150 cp worse
    - an opponent's mistake or blunder punished: your reply is within the inaccuracy threshold
    - hard defence: eval ≤ −150 before, and you played Best or Good, holding the position
    - conversion: reached ≥ +200 and won without dropping below +100
    - clean phase: ≥ 8 of your moves and no mistakes or blunders
    - decided positions (beyond ±500) are excluded
    - with nothing qualifying, a plain sentence and no praise
- [x] Review screen: Summary / What to improve (today's key moments, unchanged) / What you did well, with each item clickable to its ply. Works with no AI key.
- [x] Explain my game gets the strengths list as grounded context and a "what you did well" part. The prompt version is bumped so cached narratives aren't reused.

## Done when (adds to ROADMAP v0.14)
- Paste, chapter links and bare IDs parse; anything else makes no request.
- A text chapter is kept and shown; a chapter with moves from an invalid position is rejected; the rest are kept.
- After a 403, an old token gets the sign-in-again message; a public study never sends the token.
- Author search lists titles and opens one to add; offline and an unknown user give clear messages.
- Add to my repertoire takes the main line only unless Include side lines is on.
- Study text containing a URL renders as plain text, never a link.
- Each strength rule has positive and negative unit tests on fixture rows; a strong game shows strengths, and a game with none shows the plain sentence; the three parts work with no AI key; the Explain my game prompt includes only engine-backed strengths.

2. Add `https://lichess.org/study/nq1GGbNO` and step through "Vienna Gambit: 3...d5 crushing attack!" using the branches. Compare it with Lichess, then add its main line to your White repertoire and drill it in Practice.

7. Review a strong game of yours and read **What you did well**. Check each item against the moves.
