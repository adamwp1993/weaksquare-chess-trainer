# v0.1 plan: The puzzle mixer (MVP)

## Context
The repo has only the spec, the guardrails and `scripts/check_docs.py`. v0.1 delivers the first working app: you import the Lichess puzzle DB, choose a mix of puzzles (themes ANY/ALL, excluded themes, rating, move count, side), see a live match count, and solve a random queue in Standard mode. Attempts are saved to `user.db`. It works offline, with no account and no engine. v0.1 also locks in the foundations every later version builds on (ARCHITECTURE §3 decisions 1–17). It's built in three committed steps (a → b → c) on branch `v0.1`, with QA once at the end.

Requirement IDs in scope: FR-2.1–2.4, §4.2, FR-3.1–3.5, FR-3.11 (random only), FR-3.12, FR-3.14, FR-4.1, FR-5.1, FR-5.3, FR-5.5 (subset, below), NFR-1–7, NFR-8 (setup.py and shortcut), SR-1–3, SR-5, SR-6 (puzzle DB), SR-10, SR-12/12a (fixtures), SR-14b, SR-16.

## Design decisions (approved; each one gets an ARCHITECTURE §7 entry)
1. **Theme bitmask columns instead of a `puzzle_themes` table.** puzzles.db gets a narrow `puzzle_index` table: integer rowid, `rating`, `length`, `player_color`, `t0`, `t1`, `t2` (62 theme bits each), plus a `theme_bits(theme, bit)` table built at import, so a theme from a newer export gets a bit automatically. A covering index on `(rating, length, player_color, t0, t1, t2)` lets the rating range drive the count. REQUIREMENTS §4.3 already allows this. A 6M-puzzle × ~4-theme join table would add ~1 GB and be slower for ALL. The full theme string stays on `puzzles` so it can be revealed after the puzzle (FR-3.14). REQUIREMENTS §4.3 gets updated in the same commit.
2. **Puzzle-DB swap while connections are open.** On Windows you can't rename a file over one that's open. Every DB access goes through `db.session()`, which holds a shared lock. The swap takes the exclusive lock, closes every registered connection (none is in use at that moment), runs `os.replace(puzzles.new.db, puzzles.db)` and releases the lock, and threads then reopen lazily. puzzles.db is attached read-only (`mode=ro`, journal mode DELETE), so it has no `-wal` files.
3. **Queue building without loading 1M IDs:** if the match count is ≤ 100k, fetch the matching rowids and sample them in `core.queue` with the injected rng. Otherwise, rejection-sample random rowids in batches (`rowid IN (…) AND <filter>`). Both paths are deterministic for a given seed.
4. **SR-16 for a run-from-source app:** the app refuses to start if `WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS` contains `--remote-debugging-port`, unless it was launched with `--dev`. The smoke harness launches with `--dev`, a temp `WEAKSQUARE_DATA_DIR` and a random 127.0.0.1 port. The Start-menu shortcut never passes `--dev`.
5. **Data folder (NFR-2):** a plain launch (the shortcut) uses `%LOCALAPPDATA%\WeakSquare`, and `--dev` uses `%LOCALAPPDATA%\WeakSquare-dev`. `WEAKSQUARE_DATA_DIR` overrides both. An autouse pytest fixture sets a temp folder, and `config.py` raises if it resolves to either real folder while running under pytest.
6. **Wrong move in v0.1** (Show answer arrives in v0.2): the attempt is marked lost (FR-5.3), the board takes the move back and shows "Wrong. Keep trying", and you can keep going to see the solution line or press **Next**. Once you've failed, nothing more is recorded as a loss.
7. **Persistence you can see:** the session bar shows this session's solved / failed / accuracy, plus an "All time: N solved, M failed" line read from `attempts`. Without it, your "close and reopen" check has nothing to look at. It's a single count query, not the v0.2 Stats page.
8. **Puzzle DB integrity (SR-6):** database.lichess.org doesn't, as far as I know, publish a checksum for the puzzle file. I'll check this at build time. If a checksum is published, it's verified. Otherwise the check is HTTPS, then Content-Length, then the zstd frame checksum, then the row-count and `PRAGMA integrity_check`. The file's SHA-256 is recorded in `meta` either way. No hash is hard-coded, since the export changes every month.
9. **DTO contract:** `scripts/gen_types.py` generates `web/src/api/types.ts` from `bridge/dto.py`, and the contract test fails if the committed file is out of date.

It forwards `window.onerror` and `unhandledrejection` to `log_frontend_error`, rate-limited.
- `web/src/views/AboutModal.tsx` (NFR-7): version, data and logs folders with Open buttons, puzzle export date, license and repo link. Stockfish appears from v0.4.
- `scripts/setup.py`: idempotent. It installs uv with pip if missing, runs `uv sync --locked`, `npm ci` (via `shutil.which("npm")`), `uv run playwright install chromium` and `uv run pre-commit install`, then `fetch_puzzle_db.py` (skipped with `--skip-puzzle-db`, `--puzzle-file PATH` to use a local file), then the Start-menu shortcut to `.venv\Scripts\pythonw.exe -m weaksquare`. ### v0.1b Puzzle DB
- `src/weaksquare/core/puzzle.py`: `PuzzleRef(source, id)` (with `str()` giving `lichess:00008`), the `Puzzle` dataclass, and a `PuzzleSource` Protocol (`count`, `sample_ids`, `get`).
- `src/weaksquare/core/chess_rules.py`: `player_color(fen)`, `puzzle_length(moves)`, `length_bucket(n)`, `start_position(fen, moves) -> (board, opponent_move)`, and `is_acceptable(board, played_uci, expected_uci) -> bool` (any mate is accepted when the expected move mates).
- `src/weaksquare/core/csv_rows.py`: `parse_row(header_map, row) -> PuzzleRow | RowError`, reading by header name and tolerating extra columns such as `DailyDate` (FR-2.2).
- `src/weaksquare/core/themes.py`: the static theme catalog with key, English name and group (Phases, Motifs, Advanced, Mates, Mate patterns, Special moves, Goals, Origin), taken from lila's `puzzleTheme.xml` (AGPL, compatible). Themes it doesn't know go in an "Other" group.
- `src/weaksquare/adapters/http.py`: `HttpClient` (httpx) with a User-Agent carrying the repo URL, timeouts, retry/backoff, `download(url, dest, resume=True, progress, cancel)` using Range, and header redaction.
- `src/weaksquare/adapters/db/repos/puzzle_import.py`: writes `puzzles.new.db` in batched transactions, then builds the indexes, runs the integrity check and fills `meta`.
- `src/weaksquare/services/puzzle_db.py`: `PuzzleDbService` with `status()`, `start_import(local_path | None) -> job_id`, and `_run(progress, cancel)`. The job downloads to `.part` (resumable), stream-decompresses, imports into a fresh `puzzles.new.db`, checks the row count and integrity, and swaps it in. On cancel or failure it deletes `puzzles.new.db` and leaves `puzzles.db` alone (FR-2.3).
- `scripts/fetch_puzzle_db.py`: a thin CLI over `PuzzleDbService` with a console progress bar. Options: `--file PATH`, `--data-dir`, `--dev`.
- `web/src/views/ImportView.tsx`: shown when there's no puzzle DB. It offers Download, Use a local file and Cancel, with a Mantine Progress bar, and a "Re-import" entry in the header menu.
- `tests/fixtures/puzzles_sample.csv`: ~300 puzzles, plus `puzzles_sample.csv.zst`. The 10 Done-when puzzles are hand-checked. `GameUrl` is replaced by `https://lichess.org/GAMEID01`…, because SR-12a forbids real game IDs or URLs. It's generated once by `scripts/make_fixture.py`, which is dev-only and lives under `tests/fixtures/tools/`.

### v0.1c Mixer
- `src/weaksquare/core/filters.py`: `FilterSpec`, the full §5 schema (decision 5): themes, match_mode, exclude_themes, rating_min/max, lengths, side, openings, min_popularity, min_plays, history flags, ratios, order, queue_size/endless, source. It provides `to_json`/`from_json` and `validate()`. **v0.1 rejects non-default values for v0.2+ fields** with a clear `unsupported_in_this_version` error, rather than silently ignoring them.
- `src/weaksquare/core/queue.py`: `sample_random(ids, n, rng)` and `next_batch(...)` for endless sessions (refills in chunks of 50, no repeats within a session).
- `src/weaksquare/core/modes/base.py`: the `TrainingMode` Protocol (`start`, `on_move`, `on_help`, `result`). `core/modes/standard.py` holds `StandardMode`. A wrong move sets lost, takes the move back and lets you continue; the opponent reply is returned in the feedback; `result()` gives `AttemptResult(win, first_move_correct, line_correct, help_used='none', time_ms)`.
- `src/weaksquare/core/scoring.py`: `is_win(...)`. v0.1 implements only win/loss (help arrives in v0.2, angle in v0.3).
- `src/weaksquare/adapters/db/repos/puzzles.py`: `LichessDbSource` (implements `PuzzleSource`), `count(spec)`, `sample_ids(spec, n, rng)` (decision 3) and `get(ref)`. It owns the bitmask SQL builder.
- `src/weaksquare/adapters/db/repos/attempts.py`: `append(attempt)`, `session_stats(session_id)`, `all_time_totals()`. `repos/settings.py`: get/set. `repos/sessions.py`.
- `src/weaksquare/services/session.py`: `SessionService` with `start(spec, queue) -> session_id`, `next_puzzle(session_id) -> PuzzleDTO` (FEN after the opponent's move, the opponent move for animation, player color, **no themes**), `submit_move(session_id, uci) -> MoveFeedbackDTO` (on finish it appends the attempt and returns `ResultDTO` with the themes revealed), and `stats(session_id)`. Mode state is kept in memory per session.
- `web/src/components/`: `Board.tsx` (a chessground wrapper with chess.js dests, the animated opponent move and orientation set to the player color), `ThemePicker.tsx` (grouped checkboxes, search, Select all/Clear, ANY/ALL; reused for Excluded), `RatingSlider.tsx` (RangeSlider plus numeric inputs, bounds from `meta`), `MoveCountSelect.tsx` (1/2/3/4+/All), `SideSelect.tsx`, `MatchCount.tsx` (debounced 250 ms, drops stale responses), `QueueControls.tsx` (N or Endless), `SessionBar.tsx`.
- `web/src/views/MixerView.tsx` (filters plus Start), `TrainerView.tsx` (board, result panel with themes after the end, Next) and `web/src/state/store.ts`. The last-used FilterSpec is persisted through `set_setting`, never browser storage (decision 14).
