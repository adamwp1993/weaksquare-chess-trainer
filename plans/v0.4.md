# v0.4 plan: Stockfish

## Context
v0.3 was signed off and merged on 2026-11-02. v0.4 adds the local engine:
- a pinned, hash-checked Stockfish 19 installer, used by a script, `setup.py` and an in-app Install button
- an `EngineClient` (the interactive engine) that validates every input and survives crashes
- engine settings, including a custom engine path
- in the trainer: Stockfish's refutation of your wrong move in Show answer, plus an eval with top lines after the puzzle ends (never during it)
- an analysis board you can open after a puzzle (added at planning; see decision 3)

Work happens on branch `v0.4` from `main`. This plan is saved as `plans/v0.4.md` in the first commit and ticked off as items land.

**Requirement IDs in scope:** FR-7.1, 7.2 (refutation, MultiPV top lines, evals; the Danger-spotting use is v0.6), 7.3, 7.4, 7.5, 7.6; NFR-4 (Stockfish version on the log banner), NFR-6 (stop the engine on close), NFR-7 (Stockfish version and path on About); SR-6; §7.2 step 2 (refutation in Show answer).

**Out of scope, for later versions:**
- the *background* engine and the analysis queue: v0.8. The `EngineClient` protocol leaves room for it, but there's no code for it.
- Danger-spotting safe-candidate checks: v0.6
- the first-run wizard: v1.0
- macOS and Linux manifest entries: v1.1. Those platforms refuse with a clear message.

**Decisions from Adam (planning, 2026-11-02). REQUIREMENTS.md and ROADMAP.md are updated in the first commit to match:**
1. **Engine folder: per data folder.** Installs go to `<data folder>\engines\sf_19\`:
   - the real app: `%LOCALAPPDATA%\WeakSquare\engines`
   - `--dev` runs: `WeakSquare-dev\engines`
   - tests: a temp folder

   `fetch_stockfish.py` and `setup.py` take `--dev`, the same way `fetch_puzzle_db.py` does. FR-7.5's install-location line is reworded to match.
2. **Evals are shown from your side.** Positive means good for the side you played: "+3.2 for you", "−1.4 for you", "You mate in 3", "You're mated in 2". The raw White-relative score stays internal.
3. **Post-puzzle engine view: both, plus an analysis board.** This is a new requirement, **FR-7.7**, recorded in REQUIREMENTS.md and the ROADMAP v0.4 section:
   - The panel always shows the **puzzle's start position** eval as a pinned line.
   - Below that, it **follows the board**: the eval and top 3 lines for whatever position is shown as you step through Show answer.
   - An **Analyze** button opens a free **analysis board** on the same board. You can move pieces for either side (legal moves only, via chess.js). After each move the engine re-analyzes, showing the eval, the top 3 lines and an arrow for its best move. There are Back / Forward / Reset-to-puzzle controls and a Close button. Nothing from the analysis board is ever scored.

**None new.** python-chess (`chess>=1.11.2`) already provides `chess.engine` (UCI). Zip handling and hashing come from the stdlib.

## Design decisions (each gets an ARCHITECTURE §7 entry)

### 1. Manifest and installer (FR-7.5, SR-6)
- **`src/weaksquare/engine_manifest.json`** has `{"engines": {"stockfish": {"tag": "sf_19", "assets": {"windows-x86_64": {name, url, sha256, size, exe_member}}}}}`.
  - The SHA-256 is GitHub's published asset digest, read at build time with `gh release view sf_19 -R official-stockfish/Stockfish --json assets`. I won't compute it myself.
  - `exe_member` is the exact path of the `.exe` inside the zip. I confirm it from the real asset.
- **`core/engine.py`** (pure) holds:
  - `parse_manifest`
  - `platform_key(system, machine)`, which maps AMD64 → `x86_64`. A missing key is an `UnsupportedPlatform` with a clear message.
  - `check_zip_names(names, exe_member)`. It rejects the **whole archive** if any entry is absolute, has a drive letter or contains `..`, and returns the member to extract.
  - the FEN and move-list validation (decision 2)
  - `format_score(score, player_color)` for the "for you" wording
- **`services/engine_install.py`** (`EngineInstaller`; deps injected: `HttpClient`, `sha256_file`, a zip extractor, the probe, `Paths`):
  1. **Idempotent:** if `engines/sf_19/install.json` matches the manifest's tag and asset hash, and the exe's hash equals the recorded one, it does nothing. `force=True` reinstalls.
  2. **Download:** through `http.download` to `downloads/<asset>.part`, with progress and cancel.
  3. **Verify before extracting:** check the SHA-256. On a mismatch it deletes the file and fails with `checksum_mismatch`.
  4. **Extract and check:**
     - `check_zip_names`, then extract only `exe_member` into `engines/.sf_19.tmp-<n>/stockfish.exe` (`adapters/files.py: extract_member`)
     - probe it (`uci` → `uciok`, then a 0.2 s search from the start position must give a legal move)
     - write `install.json` with the tag, asset sha, exe sha, the engine's `id name` and the install time from the Clock
  5. **Swap into place:** rename the temp folder to `engines/sf_19`. With `force`, the old folder is renamed aside first and deleted after a successful swap. If the exe is locked because the app is running, the error says to close the app.
  6. **Clean up:** delete the zip. On any failure, remove the temp folder and the `.part` file, so nothing is left behind.
  - It runs as a `stockfish_install` job in the app (progress events, cancellable), or synchronously from the script.
- **`scripts/fetch_stockfish.py`** is a thin CLI over the service. It takes `--dev` and `--force`, prints progress and returns a non-zero exit code on failure.
- **`scripts/setup.py`** gets a **Stockfish step** after the puzzle step. It runs `uv run python scripts/fetch_stockfish.py` and passes `--dev` through. `--skip-engine` skips it.

### 2. `EngineClient` (FR-7.1, 7.6, ARCH decision 12)
- **The protocol** (in `core/engine.py`):
  - `analyse(board, think_s, multipv) -> list[EngineLine]`, where an `EngineLine` holds the score (White-relative cp or mate) and the pv as UCI
  - `probe(path) -> EngineInfo`
  - `configure(threads, hash_mb)`
  - `close()`
  - The docstring notes that v0.8 adds a second (background) instance, not new methods.
- **`adapters/stockfish.py`, `StockfishEngine`:** one python-chess `SimpleEngine`, started **lazily** on the first request and kept running until the app closes.
  - **One request at a time:** a lock serializes requests, and each one has a hard timeout of `think_s + 10 s`. On a timeout it kills the process, restarts it once and fails that request with `engine_timeout`, so a call can never hang.
  - **Crash recovery:**
    - a logging handler on the `chess.engine` logger keeps the engine's last output lines
    - on `EngineTerminatedError` it logs the `info string CRITICAL ERROR …` line if one is there
    - it restarts once and raises `EngineError("engine_crashed", "Stockfish stopped unexpectedly and was restarted. Try again.")`
    - the next request works
  - It applies `Threads` and `Hash` when the settings change.
- **`services/engine.py`, `EngineService`:**
  - **Which binary:** the custom path if set, otherwise the managed install. Otherwise it reports `not_installed`.
  - **Validation (FR-7.6):** every FEN and move list goes through `core.engine.validate_fen` / `validate_line` (python-chess `Board.is_valid()`, legal moves) **before** the adapter sees it. Positions that are already over (mate or stalemate) answer without the engine.
  - **Latest request wins:** each analysis request carries a generation number per session, and an older queued request returns `superseded` at once. Stepping fast through a line runs one search, not ten.
  - **Engine calls are bridge calls the UI awaits** (≤ think time + a little), not jobs. The UI shows "Stockfish is thinking…" and never disables other controls. This is recorded as a §7 refinement of decision 7.
- **Shutdown (NFR-6):** `app.py` closes the engine on exit. The NFR-4 banner line adds `Stockfish: sf_19 (managed) | custom | not installed`.

### 3. FR-7.3 enforced in the backend, not just the UI
- `SessionService` exposes `get_refutation(session_id)` and `analyze(session_id, fen)`. Both **refuse with `conflict`** unless the current puzzle is **finished**: line complete, or Show answer used.
  - A decided-but-unfinished puzzle, after a wrong move while you keep playing, still counts as in progress, so no eval leaks.
- The analysis board calls the same `analyze(session_id, fen)` with the FEN validated server-side. It's only allowed after the finish too.

### 4. Refutation in Show answer (§7.2 step 2, FR-7.2)
- `StandardState` records `first_wrong: (fen_before, uci) | None`, the move that decided the loss.
- `HelpResult` for `answer` gains `refute: bool`, set when there is a first wrong move.
- `get_refutation` analyses the position after the wrong move (MultiPV 1, the think time) and returns:
  - the position before it
  - the wrong move
  - the reply line, trimmed to 3–5 plies (fewer if the game ends)
  - the "for you" eval

  It's cached in the session.
- **UI:** `AnswerPlayer` gets **segments**: "Your move Nf3?: why it fails" (the wrong move, then the refutation line), then "The solution". Show answer appears at once. The refutation segment fills in when it's ready and the player starts there. If the engine isn't installed or fails, only the solution shows, with the install banner or a short error in place of the segment.

### 5. Post-puzzle engine panel and analysis board (FR-7.2, 7.3, new 7.7)
- **`components/EnginePanel.tsx`** renders **only when the puzzle is finished**. It shows:
  - the pinned start-position line
  - the current position's eval and 3 lines in SAN (first 8 plies each, converted with chess.js)
  - a "thinking" state, debounced by 250 ms

  Text is plain React text, never HTML.
- **`components/AnalysisBoard` state in TrainerView:**
  - Analyze swaps the board into free-move mode for both colors, keeping its own move list with Back / Forward / Reset / Close.
  - The best move is drawn as a chessground arrow. The UI checks the move is legal with chess.js before drawing it.
  - Leaving the puzzle (Next) closes it.
- **The not-installed state:** wherever an engine feature would appear, `EngineInstallBanner.tsx` shows *Stockfish isn't installed* with an **Install** button, which runs the job with progress through `useJob`. It appears in the refutation spot, the engine panel and the Settings engine section.

### 6. Engine settings (FR-7.4, 7.5)
- These are stored in the existing `settings` table, so there's **no migration**. They're validated in the service:

| Setting | Default | Allowed range |
|---|---|---|
| `engine.think_s` | 1.0 | 0.2–10 s |
| `engine.threads` | CPU cores − 1, min 1 | 1–CPU cores |
| `engine.hash_mb` | 256 | 16–2048 MB |
| `engine.custom_path` | null | — |

- A **custom path** is accepted only after the same probe passes. The probe runs as a short job, because a bad exe can take seconds. A failing path isn't saved and says why. **Use the managed engine** clears it.
- **The Settings modal** gets an **Engine** section:
  - status (version, managed or custom)
  - Install / Reinstall
  - the three number inputs
  - the custom path with Browse… (`Desktop.choose_engine_file`, `.exe` filter) and Clear
- **About** shows the Stockfish version and path (NFR-7).

### 7. Bridge additions (allowlist test updated in the same commit)
| Method | Returns |
|---|---|
| `get_engine_status` | `EngineStatus`: state `ready` / `not_installed` / `unsupported_platform` / `custom_invalid`, source, version, path |
| `start_engine_install(force)` | job id |
| `get_engine_settings` | `EngineSettings` |
| `set_engine_settings(...)` | `EngineSettings` |
| `choose_engine_file` | a path, or nothing |
| `start_custom_engine_check(path)` | job id; saves the path on success |
| `clear_custom_engine` | nothing |
| `get_refutation(session_id)` | `Refutation` |
| `analyze_position(session_id, fen, purpose)` | `Analysis`; `purpose` is `panel` or `board`, used for the latest-wins generation |

The DTOs go in `bridge/dto.py`. Then I regenerate `types.ts` with `gen_types.py`, update `ApiClient`, `pywebviewClient` and `mockClient` (fixed, deterministic engine answers, plus a "not installed" mock state for screenshots and e2e).

## Tests (each bug fix later adds a regression test)
- **Unit (core):**
  - `platform_key`, `parse_manifest`, `check_zip_names` (`..`, absolute, drive letter, missing exe)
  - `validate_fen` / `validate_line`
  - `format_score` (cp and mate, both colors)
  - Standard mode: `first_wrong` and `refute`
- **Installer integration** (httpx `MockTransport` serving a fake zip; probe faked):
  - a clean install creates `engines/sf_19` and deletes the zip
  - **a hash mismatch refuses and leaves nothing behind** (no `.part`, temp folder or `engines/sf_19`)
  - **a zip with `..` paths is rejected**, with nothing extracted
  - **a second run makes no HTTP request**
  - `--force` reinstalls
  - a probe failure removes the install
  - cancel cleans up
  - an unsupported platform refuses
- **Engine adapter with the fake UCI engine** (normal suite, CI):
  - **an invalid position sent past validation causes one restart and a clean `engine_crashed` error**, the CRITICAL ERROR line is logged, and the next request succeeds
  - a hang produces `engine_timeout` within the bound
  - a crash during the restart itself gives a clean error, with no loop
- **Service integration:**
  - FR-7.3 gating: `analyze`/`get_refutation` refuse during a puzzle, including after a wrong move, and work after the finish
  - the refutation is 3–5 plies
  - latest-wins supersede
  - settings validation and persistence
  - the custom path is rejected when the probe fails
- **`@pytest.mark.engine`** (real Stockfish; skipped when it isn't installed): **a known position gives the expected best move** (a fixed mate-in-1 and a hanging-queen capture); the real Stockfish 19 crash-and-restart check; probe version `Stockfish 19`.
- **Contract:** the allowlist, DTO ↔ `types.ts`, the manifest schema test (the SHA is 64 hex characters, the URL is https on github.com, the key is `windows-x86_64`), no browser storage.
- **Playwright (mock client):**
  - **no eval or engine line is visible while solving**: at the start, after a correct move, after a wrong move and after a Hint
  - the panel appears after the finish
  - the refutation segment comes before the solution
  - the analysis board makes a move, the eval updates, the arrow is drawn, then Reset and Close
  - the install banner → the job progress → ready
  - the Settings engine section validates input
  - About shows the version
- **Real-app smoke (QA):** the app starts with no engine and shows the banner; with a temp data folder, Install works end to end.
- **Docs screenshots:** the engine panel, the refutation, the analysis board, the install banner, the Settings engine section.
