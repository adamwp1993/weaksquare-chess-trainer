# v0.10 plan: Coach

## Context
v0.9 is signed off and merged (`main` is clean). ROADMAP v0.10 adds the Coach on top of the v0.8 analysis pipeline and the v0.7/v0.9 LLM stack:
- the lichess-puzzler tagger and habit tags
- multi-game aggregation, the free report, the gap table and the puzzle-history source
- the Suggested default mix and its banner
- optional LLM coaching
- Puzzles from your games
- two Game Review additions: Analyze from here and Show best moves

Exploration found these gaps:
- Nothing writes `game_analysis.themes` or `custom_puzzles.themes` / `solve_as` / `status`.
- `MY_ORIGINS` has no `coach`, and `FilterSpec` has no severity filter.
- `FEATURES` has no `coach`.
- There's no puzzle-dashboard client and no tracking of whether you changed the filters by hand.
- The puzzle engine call (`analyze_position`) is tied to a session.
- lichess-puzzler is in neither the repo nor PyPI.

Branch: `v0.10` from `main`. Check `git status` / `git branch` first (memory).

## Decisions from Adam (2026-11-04, v0.10 planning)
| Question | Answer |
|---|---|
| Rule for a clean puzzle (FR-10.41) | **Port Lichess's generator rules.** The best move must beat the second best by more than 0.7 in win chances (configurable). Use the mate-in-1 rules, extend the line while your move stays the only good one, trim to an odd length, and drop 1-move advantage puzzles. Each extension position gets about 1 s on the background engine, not Lichess's 30 s. The tagger (`cook.py`, `util.py`, `model.py`) is vendored at a pinned commit. |
| When puzzles are generated | **After any analysis:** Coach runs, Analyze selected and Review, all in the one pipeline. A one-time backfill job covers games that are already analyzed. |
| Think time | **One setting, 0.3 s** (Review's `review.think_s`). Every game the Coach analyzes opens in Game Review without a re-analysis. FR-10.9 is updated, and Lichess's own evals aren't used (FR-11.3). |
| Accounts | **Your linked usernames by default, plus an option to enter any username or profile URL** and analyze that player. |
| Another player's games | **Report only, kept apart:** their games are tagged with that player and hidden from My Games except through a new **Player** filter. The run saves a report labeled with their name, and Load preset still works. It never changes your Suggested mix, creates no My puzzles, and never counts in your stats or report trends. |
| AI for another player | **Yes, with the same guardrails.** The prompt carries no username. |

**My own choices (veto at approval if wrong):**
- **Shared games:** a game between you and that player is stored once. A new `game_subjects` table records whose games a game counts for. Analysis is per position, so both sides reuse it.
- **No checkpoints, statuses or Progress page** (v1.0). In v0.10, weaknesses are ranked by game rate × severity. The label reads *"Suggested — from Coach run #N, <date>"* until checkpoints exist; FR-10.28 gets a note.
- **Manual-change rule:** a new suggestion replaces the current filters only if they still equal the default broad mix or the last suggestion you applied. Otherwise you get the banner (Apply / Compare / Dismiss).
- **One drill mode per suggestion:** the mode comes from the top weakness, using its mistake reasons (FR-10.29, which needs at least 5 tagged misses). "Why this mix" names the drills for the other weaknesses.
- **FilterSpec changes** (saved-filters version 4, with `upgrade_saved`):
  - `my_severities` (FR-10.40 filter)
  - `my_share` (the % of own-game puzzles when the source is Both; default None keeps today's proportional mix)
  - optional `lengths` on `RatioBucket`, so long combinations get their own share
- **Opening moves:** the Coach skips the first 6 moves and positions already decided (±500 cp) when it aggregates and when it makes puzzles. Review grading is unchanged.
- **Rating band:** centered on your Lichess puzzle rating, or estimated from local first-try accuracy, ±150. It's nudged by 100 when your recent accuracy in that band is outside 65–85%, aiming for about 75%.
- **Imported puzzles** have no previous move. They're tagged with a null-move stand-in, which skips the tags that depend on that move.
- **Danger spotting stays Lichess-only** for My puzzles, as FR-3.15 already says. FR-10.42's "can also feed Danger spotting" isn't built.

## Out of scope (later versions)
- v1.0: checkpoints, `weakness_metrics`, statuses, the Progress page, the auto AI summary, notifications.
- v0.11: digests, whole-game measures, Advanced analysis, lesson links, notes.

## Dependencies
- **No new PyPI or npm packages.**
- **Vendored code:** `src/weaksquare/vendor/lichess_puzzler/` holds `cook.py`, `util.py` and `model.py` from a pinned commit, plus `LICENSE` (AGPL-3.0) and a `README` with the commit hash, the source URL and the patch.
  - The patch: imports made relative, and the logging and URL-building `log()` removed.
  - The files only import python-chess and the standard library; a contract test enforces this.
- Docs: an ARCHITECTURE §7 entry and a §2 layout update, REQUIREMENTS §15 (now "vendored, not a dependency") and FR-10.41 ("already a dependency" corrected).
