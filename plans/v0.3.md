# v0.3 plan: Lichess account + sync

## Context
v0.2 was signed off and merged on 2026-11-01. v0.3 connects the app to your Lichess account:
- sign in with PKCE and a loopback listener, with the token kept in Windows Credential Manager
- a startup page, and a gear icon for account settings
- every v0.3 attempt is queued and synced to Lichess with a truthful angle
- your puzzle history is imported for the "exclude played on Lichess" filter and the "already played" badge
- your Lichess puzzle rating is shown: in the header, per puzzle, as a session total, and as a trend on Stats

Work happens on branch `v0.3` from `main`. This plan is saved as `plans/v0.3.md` in the first commit and ticked off as items land.

**Requirement IDs in scope:** FR-1.1, 1.5, 1.6 (Lichess part), 1.7, 1.8 (account section plus the existing settings), 1.9, 1.11 (Lichess part only); FR-6.1–6.17 including 6.11a–d and 6.16a; FR-9.4; SR-1, 2, 4, 5, 7–10, 12, 12a, 13, 15; and the FR-3.9 "exclude played on Lichess" filter.

**Out of scope, for later versions:**
- LLM provider, model and key fields (FR-1.2–1.4, 1.10): v0.7
- the chess.com username and Verify (FR-1.11's chess.com part): v0.8
- game sync: v0.8
- spaced repetition: v0.5. The "already played" badge is built now for Standard mode.

**Decisions from Adam (planning, 2026-11-01). REQUIREMENTS.md is updated in the first commit to match:**
1. **Pre-v0.3 attempts are never synced.** The migration marks them `sync_status = 'local'`. Only attempts recorded from v0.3 on enter the queue.
2. **Angle when only the move count is narrowed:** use the puzzle's length theme (`oneMove` / `short` / `long` / `veryLong`, which line up exactly with 1/2/3/4+). Priority when several match:
   - selected motif-type themes first (the Motifs, Advanced, Mates, Mate patterns and Special moves groups)
   - then Phases / Goals / Origin
   - then length
   - With ratios, the "selected themes" are every group's themes, in group order.

   This is added to FR-6.14.
3. **The rating chart uses `@mantine/charts` + `recharts`** (new npm dependencies; see Dependencies).
4. **"Exclude played on Lichess" is on by default.** Saved filters get it once through `upgrade_saved` (`SAVED_FILTERS_VERSION` 3). With no imported history it changes nothing.

## Design decisions (each gets an ARCHITECTURE §7 entry)

### 1. `SecretStore` (SR-1, SR-7, SR-8, FR-6.5, FR-6.7)
- `adapters/secret_store.py` is the only module that imports keyring.
  - It provides `SecretStore` (a Protocol with `get`, `set` and `delete` on `(service, account)`), `KeyringSecretStore` and `FakeSecretStore`.
  - Service names: `weaksquare` for normal runs and `weaksquare-dev` for `--dev`, so a dev run never touches your real sign-in (the spirit of NFR-2). The test token uses `weaksquare-test`. The account name is `lichess`.
  - keyring errors are re-raised as `SecretStoreError` without the value.
- Tokens up to 1,200 characters are allowed. Credential Manager's 2,560-byte blob limit, with keyring's UTF-16 encoding, allows 1,280, which satisfies FR-6.7's "at least 512". A longer token fails with a clear error.
- Services fetch the token per request and pass it straight to `http.py`. It never goes into a DTO, the log or an exception message.

### 2. HTTP additions (`adapters/http.py`)
- New methods: `get_json`, `post_form`, `post_json`, `delete` and `stream_ndjson`. Each takes an optional `token=` that becomes a per-request `Authorization: Bearer` header, never a client default.
- New `HttpError` subclasses: `Unauthorized` (401) and `RateLimited` (429, with `Retry-After` if Lichess sends one).
- A 429 is **not** retried inside the client. The sync service waits at least 60 s, as Lichess asks.
- SR-10: a logging filter (in the existing `logging_setup`) redacts `lip_…`, `li_…`, `Bearer …` and `sk-…`, and keeps httpx/httpcore at WARNING. A unit test covers it.

### 3. `LichessClient` (`adapters/lichess.py`, a Protocol plus an httpx implementation; the fake is in `tests/fakes/lichess.py`)

| Method | Lichess call |
|---|---|
| `authorize_url(challenge, state, redirect)` | builds the `/oauth` URL |
| `exchange_code` | `POST /api/token` |
| `revoke` | `DELETE /api/token` |
| `account` | `GET /api/account` → username, `perfs.puzzle.{rating, prov}` |
| `solve_batch(angle, solutions)` | `POST /api/puzzle/batch/{angle}?nb=0` → `rounds[{id, win, ratingDiff}]` and `glicko{rating, deviation, provisional}` (shape from the spec schema; the live test confirms it) |
| `activity(since_ms)` | streams `GET /api/puzzle/activity` (ndjson `{date, win, puzzle{id,…}}`) |

`client_id` is `weaksquare-chess-trainer` and `scope` is `puzzle:read puzzle:write`.

### 4. PKCE sign-in (FR-6.1–6.3, FR-6.1a, SR-4, SR-9)
- `core/oauth.py` (pure): `make_verifier(rng)`, `challenge(verifier)` (S256, base64url without padding), `make_state(rng)` and `parse_callback(query, expected_state)`.
  - The verifier and state are 32 random bytes. I make them with `secrets.token_urlsafe` in the adapter rather than the app's seeded `random.Random`, because a seeded generator isn't fit for secrets.
  - `core` receives the strings, so tests stay deterministic.
- `adapters/oauth_loopback.py` binds `127.0.0.1:0` (a random port) with stdlib `http.server`.
  - It accepts exactly one `GET /callback`, answering any other path with 404 without consuming the listener.
  - It replies with a plain "Signed in. You can close this tab and return to WeakSquare." page, then shuts down. It also shuts down after 5 minutes or when cancelled.
  - The query string is never logged. Each request handler's `log_message` is silenced.
- `Desktop.open_in_browser(url)` (stdlib `webbrowser`) and `Desktop.bring_to_front()` (reusing `instance_lock`'s window-raising code).
- `services/account.py: AccountService.start_sign_in()` runs an `lichess_sign_in` job:
  1. listen
  2. open the browser
  3. wait for the callback
  4. exchange the code
  5. store the token
  6. call `account()`
  7. raise the window
  8. start the history import, then a sync

  Its failure messages are user-facing: *cancelled*, *timed out*, *state mismatch*, *Lichess refused*, *offline*.

### 5. Account state, fast path and sign-out (FR-1.1, 1.6, 1.7, FR-6.4, 6.6)
- `AccountService.status()` returns `{state: signed_out | checking | signed_in | offline | expired, username, rating, provisional}`.
  - At launch, a stored token is checked with `GET /api/account` in a short job.
  - A network failure gives `offline`: you can continue, the queue waits, and the sync retries.
  - A 401 deletes the token and gives `expired` ("Sign in again", FR-6.4).
- The last username is cached in `settings` (`lichess.account`, not a secret), so the startup page can say *Continue as `<name>`* while it checks, or when offline.
- **The header rating** (FR-6.11a) comes only from `account()` or from a sync response's `glicko`. It's kept in memory and in `settings` for the trend's latest point, never computed locally. It's hidden unless the state is `signed_in`.
- **Sign out:** `revoke()`, then delete the local token.
  - If Lichess can't be reached, the UI offers *Remove from this PC anyway*, with a note to revoke at lichess.org/account/security.
  - Pending solves stay queued.

### 6. user.db migration `0003_lichess.sql` (new file; nothing edited)
- New nullable columns on `attempts`:
  - `rated INTEGER`, `angle TEXT` and `sync_status TEXT` (`local` / `pending` / `synced` / `skipped` / `failed`)
  - `sync_account TEXT`: the username you were signed in as when you solved it. NULL means you weren't signed in, so it goes to the next account that signs in. A solve made as account A never syncs to account B.
  - `already_played INTEGER`, `rating_diff INTEGER`, `rating_after INTEGER` and `synced_at TEXT`
  - Index `attempts_sync(sync_status)`.
  - Existing rows: `UPDATE attempts SET sync_status='local'` (decision 1).
- New table `lichess_history(puzzle_id TEXT PRIMARY KEY, played_at TEXT, win INTEGER)`. It's a re-importable cache for the signed-in account and is cleared when a different account signs in.
- New settings keys: `lichess.history_since_ms` and `lichess.account`.

### 7. Angle rule (`core/scoring.py: angle_for(spec, puzzle_themes, length) -> str`, FR-6.13–6.15)
- `mix` if and only if `spec.all_themes and spec.all_lengths and not spec.ratios`.
- Otherwise the first entry, in the fixed priority order (decision 2), of the selected themes (or every ratio theme) that the puzzle has.
- If no selected theme matches (only possible if the data is odd), fall back to the length theme. The length theme is used when only the move count is filtered.
- Exclude-themes, openings, rating, side, quality and history filters don't affect the angle.
- `rated = session.rated` (FR-1.9 / 6.15). The angle is stored on the attempt when it's recorded.
- Unit tests cover:
  - all/all → mix
  - one theme
  - several selected themes in ANY and in ALL mode, checking the priority
  - motif vs phase
  - only the move count narrowed, for each length
  - ratios
  - excluded themes only → mix
  - an opening filter only → mix
  - Rated off → `rated: false`

### 8. Sync (`services/sync.py: SyncService`, FR-6.8–6.12, 6.16, 6.16a)
- A recorded attempt gets `sync_status='pending'` and `already_played`, and then `kick()` runs.
  - `already_played` = the puzzle is in `lichess_history`, or an earlier attempt here is pending or synced.
- `kick()` starts one `lichess_sync` job unless one is already running. The job:
  1. Takes the pending rows for the current account (and rows with NULL `sync_account`), oldest first.
  2. Groups them by angle, in batches of at most 99.
  3. Calls `solve_batch` for each batch.
  4. On success, records each returned round's `ratingDiff` and sets `synced`. The batch's `glicko.rating` goes on the batch's last attempt as `rating_after`, and the header rating is updated.
  5. Ids Lichess didn't return are marked `skipped` (FR-6.12).
  6. Synced ids are added to `lichess_history`.
- Nothing is marked synced without a 2xx response (FR-6.16a). A timeout leaves the rows pending, and they're resent later.
- **Backoff:** on a network error or a 5xx, the retry is scheduled after 30 s → 1 m → 2 m → … up to 10 m. On a 429, at least 60 s or the `Retry-After` value.
  - Retries go through an injected `Scheduler` (a `threading.Timer` adapter in `app.py`; a fake in tests), so the service never sleeps or reads the time itself.
  - A 401 stops the sync and switches the account to `expired`.
  - A 400 marks that batch `failed` with its logged status (it isn't retried forever) and tells the UI.
- Sign-in, the launch check and every recorded attempt call `kick()`. Solving never waits for the sync (FR-6.16).
- **Push event** `sync` carries `SyncStatus {pending, state: idle|syncing|offline|waiting, account, rating, provisional}` plus the updated `AttemptRating` rows. The UI can also poll `get_sync_status()` and `get_attempt_ratings(ids)`, because events can be dropped.

### 9. History import (FR-6.17)
- A `lichess_history_import` job runs after sign-in and on each launch while signed in.
- It streams `activity(since=lichess.history_since_ms)`, upserts `lichess_history` in chunks of 1,000, and saves the newest `date` + 1 as the next `since`, but only after the stream completes. A broken stream retries from the old `since`, which is safe because the upsert is idempotent.
- If a different username signs in, the history table and `since` are cleared first.

### 10. "Exclude played on Lichess" filter (FR-3.9)
- `FilterSpec.exclude_played_on_lichess` leaves `later`, so validation now accepts it, and its default becomes True (decision 4).
- In SQL it's `p.id NOT IN (SELECT puzzle_id FROM lichess_history)`.
- The count and the sampler use v0.2's subtraction trick, generalized: the count without the history filters, minus the matching puzzles whose IDs are in (solved ∪ played on Lichess), found through the unique `id` index. That keeps the default count near v0.2's ~315 ms. A full-DB test checks it with 20k fake history IDs.
- In the UI the checkbox shows how many puzzles you've played on Lichess, or *Sign in to use* (disabled) when you're signed out and no history is imported.

### 11. Bridge additions (allowlist test updated in the same commit)
- New methods:
  - `get_account_status()`
  - `start_sign_in()` → job ID
  - `cancel_sign_in()`
  - `sign_out(force_local: bool)`
  - `get_sync_status()`
  - `get_attempt_ratings(attempt_ids: list[int])`, at most 200 IDs
  - `get_rating_history()`
- `start_session(spec, rated: bool)` gets the new `rated` argument.
- `Outcome` gains:
  - `attempt_id`
  - `rating: RatingInfo {status: syncing | offline | unrated | already_played | not_rated | done, diff}`
- `SessionStats` gains `rating_change` (summed only from returned diffs, FR-6.11c).
- `PuzzleView` gains `already_played` (the badge).
- The DTO types are regenerated with `gen_types.py`, and `mockClient` implements everything.

### 12. Front end
- **`views/StartupView.tsx`** is shown at every launch, before the main page (FR-1.1/1.5/1.6/1.7):
  - **Signed out:** Sign in with Lichess, and Continue without signing in. The status line reads *Not signed in*, *Waiting for you in your browser… (Cancel)* or *Sign-in failed (reason)*.
  - **Fast path:** *Continue as `<username>`*, plus a "Show all options" link (Sign out, Sign in as someone else).
  - **Offline with a stored token:** *Lichess can't be reached: continue offline as `<name>`; solves will sync later.*
  - The first-run puzzle import still follows on the main page.
- **Header:** the puzzle rating (`1834`, or `1500?` while provisional) and a sync chip (*Syncing…*, *Offline: N solves waiting to sync*). A **gear** icon opens `SettingsModal`, which gains an **Account** section (signed-in name, Sign in / Sign out). Its existing appearance, sound and update sections stay, and ☰ → Settings… opens the same dialog.
- **Mixer:** a **Rated** switch next to Start (default on at each launch, not saved, FR-1.9), and the new history checkbox.
- **Result panel** (FR-6.11b):
  - `+8` in green or `−12` in red
  - otherwise *Syncing…*, *Will sync later*, *Unrated (Rated is off)*, *Already played: rating unaffected* or *Not rated by Lichess*
  - a tooltip about themed angles weighing less than `mix`

  It updates from the `sync` event, polling `get_attempt_ratings` every 2 s while the status is syncing.
- **Board header:** the badge *Already played on Lichess: rating unaffected*.
- **Session bar:** *+34 this session*.
- **Stats:** a "Lichess puzzle rating" section with a `LineChart` (`@mantine/charts`) of `rating_after` over time and a per-session change table. When nothing has synced yet, it shows an empty-state line.
- **No browser storage** anywhere (the existing contract test keeps guarding this).
- The e2e helpers get `continue_past_startup(page)`, and existing specs call it. The mock client gets a `?account=signed_out|signed_in|offline|expired` query for tests and screenshots.

### 13. Scripts and live test (SR-13)
- **`scripts/set_test_token.py`:** a `getpass` prompt that checks the token looks like a Lichess one (`lip_` plus a length check, without echoing it) and stores it with `secret_store` under `weaksquare-test`. `--delete` removes it. **Adam runs it himself in PowerShell.** I never run it.
- **`tests/live/test_lichess_live.py`** (`-m live`, skipped when the token is missing). Adam runs it with `uv run pytest -m live`. It:
  1. calls `account()`
  2. calls `solve_batch("mix", 3 × rated:false)` with 3 puzzle IDs from the fixture
  3. reads `activity(max=3)`
  4. asserts the response shapes
  5. if `--record-lichess` is given, writes **scrubbed and anonymized** copies to `tests/fixtures/http/lichess/`: username → `player_a`, IDs and URLs replaced, dates fixed, no headers kept
- The fake client is checked against those recordings. Until Adam runs the live test, the fixtures are hand-written from the API spec schema and labeled that way. The handoff asks him to run it so the real shape replaces them before sign-off (FR-6.11).
- The `test_fixtures_clean.py` scan already covers every file under `tests/fixtures`. I add the Lichess patterns it should catch: `lip_` that isn't `lip_FAKE`, and `access_token` fields.
