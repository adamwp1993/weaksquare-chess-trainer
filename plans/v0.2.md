# v0.2 plan: Mixer complete + basics

## Context
v0.1 shipped the MVP mixer (signed off 2026-11-01). v0.2 finishes the mixer and adds the basics around it:
- the remaining filters, ratios, ordering and presets
- Hint and Show answer from the dataset solution
- a basic Stats page
- keyboard shortcuts and a coordinates toggle
- dark mode and move sounds
- the importer wording
- a desktop shortcut and app icon
- the puzzle-DB update check

Work happens on branch `v0.2`, created from `main` when the plan is approved. The approved plan is saved there as `plans/v0.2.md` and ticked off as items land.

**Requirement IDs in scope:** FR-1.12, FR-1.13, FR-2.1a, FR-2.5, FR-3.6–3.11, FR-3.13, FR-5.2 (Hint and Answer), FR-5.4, FR-5.5 (`help_used`), §7.2 steps 1–2 (no engine), FR-9.1 (theme, length and rating band; one mode exists), FR-9.2, NFR-8a. **Carried over from v0.1 QA:** B14 (regenerate `solved.png`) and B15 (when a typed rating applies).

**Decisions from Adam (planning, 2026-11-01). REQUIREMENTS.md is updated in the first commit to match:**
- **Sounds (FR-1.13):** all four Lichess Enigmahack sets ship: **sfx** (default), **piano**, **nes** and **futuristic**. They're AGPLv3+ per lila's `COPYING.md`, which I checked. A **sound set** picker sits next to the on/off toggle and the volume. Lichess's "standard" set is a non-free exception there, so it's not used.
- **Quality (FR-3.8):** on by default with a light filter, **popularity ≥ 50 and plays ≥ 100**, adjustable (and you can clear either field to turn it off). Before the handoff I measure how many puzzles the defaults remove on the full DB and report it.
- **History (FR-3.9):** *Exclude solved here* hides puzzles you've **won at least once** in this app. It's a checkbox you can turn off at any time, but it's **on by default**, so puzzles you've already solved don't come back unless you ask for them. Puzzles you've only failed can still come up. *Only my misses* (off by default) shows puzzles whose **latest** attempt was a loss. *Exclude played on Lichess* stays v0.3.

## Design decisions (each gets an ARCHITECTURE §7 entry)
1. **puzzles.db schema v2, upgraded locally with no download.**
   - The new migration `puzzles/0002_openings_quality.sql` adds `opening_family` and `opening_variation` (integer ids into a new table `openings(id, tag, family_id, count)`).
   - `puzzles_indexes.sql` widens the covering index to `(rating, length, player_color, t0, t1, t2, popularity, nb_plays)` and adds `(opening_family, rating)` and `(opening_variation, rating)`.
   - An existing v1 `puzzles.db` is read-only and has no download left, so the app detects the old schema at launch and runs an **"Upgrade puzzle database"** job. The job streams rows from the current `puzzles.db` through the same `PuzzleDbWriter` into `puzzles.new.db`, then swaps (FR-2.3 safety; about 2 minutes, with progress). Until it finishes, the mixer shows the progress view.
   - The writer gets a second row source (`ExistingDbSource`) next to the CSV source, so there's no second import path.
2. **Opening filter (FR-3.7):** a searchable Mantine `MultiSelect` with families and their variations, grouped by family. SQL: `(p.opening_family IN (…) OR p.opening_variation IN (…))`. The list is served by `get_opening_catalog()` with counts.
3. **History filters (FR-3.9)** join the attempts in `user.db` by puzzle ID. *Exclude solved:* `p.id NOT IN (SELECT puzzle_id FROM attempts WHERE puzzle_source='lichess' AND win=1)`. *Only my misses:* `p.id IN (<ids whose latest attempt lost>)`, which uses the unique `puzzles_id` index, so both stay fast. The count and the queue share the same `build_where`.
4. **Ratios (FR-3.10):**
   - Each bucket is the base filters with the base themes replaced by the bucket's themes (ANY). Weights are whole percentages summing to 100, and validation checks the sum.
   - For each queue slot, `core.queue.pick_bucket(weights, rng)` picks a bucket by weight. The slots are then filled per bucket with the existing samplers, never repeating a puzzle across buckets.
   - An empty bucket is dropped and the others are renormalized, and the UI shows a warning with the bucket's count. Each bucket shows its own live count.
5. **Order (FR-3.11):** *Easy → hard* sorts a fixed-size queue by rating. With **Endless**, each refill of 50 is sorted, which the UI says. *Grouped by theme* groups by the first selected theme a puzzle has (with ratios: by bucket; with no themes selected: by the puzzle's first theme). Groups follow the selection order, so all the forks come, then all the pins. Pure functions in `core/queue.py` take `(key, rating, themes)` rows.
6. **Presets (FR-3.13):** a `user/0002_presets_stats.sql` table `presets(name PK, filters_json, created_at, updated_at)`. Presets are validated through `FilterSpec.from_json` both on save and on load. A preset that's invalid in this version loads with a clear error and is never silently changed. Bridge methods: `list_presets`, `save_preset(name, spec, overwrite)`, `rename_preset`, `delete_preset`. Names are 1–60 characters and unique (case-insensitive).
7. **`TrainingMode.on_help(state, kind)`** (FR-5.2, §7.2):
   - **Hint** returns the from-square of the next player move. **Answer** returns the rest of the solution from the current position, with a sound kind per move.
   - Help before the attempt is decided records it as a loss, with `help_used` = `hint` / `answer`.
   - After the attempt is decided, help is free and records nothing (FR-5.4). Mid-puzzle, Show answer unlocks only after Hint; once the attempt is decided, Show answer is available directly.
   - The answer player steps with Back / Forward, starting from the position where you were stuck. The refutation of a wrong move is v0.4.
8. **Stats (FR-9.1, 9.2):**
   - The migration adds a nullable `attempts.puzzle_rating` column (decision 4: new nullable columns only), so the rating bands use the rating you actually faced and survive a re-import. v0.1 attempts get it filled from `puzzles.db` where the puzzle still exists.
   - `services/stats.py` groups by theme, length (1/2/3/4+) and 200-point rating band. For each group it reports attempts, accuracy and the "first move right, line wrong" rate. Attempts on puzzles the database no longer has fall into a "no longer in the database" row (FR-2.4, left join).
9. **Move sounds are classified in the backend** so pytest can unit-test them (there's no JS test runner). `core/move_sounds.py: sound_for(board, move) -> "move" | "capture" | "check" | "checkmate" | "castle"`, by priority: mate > check > capture (including en passant and promotion with capture) > castle > move.
   - `PuzzleView.opponent_sound`, `MoveFeedback.move_sound` / `reply_sound` and each answer step carry the kind. "Puzzle solved" and "failed" come from the outcome.
   - Front end: `web/src/sound/player.ts` creates `Audio` elements lazily, only while sounds are on (so off loads nothing), and stops the previous sound before playing the next. A castle plays the move sound, because none of the sets has a castle sound.
   - Files go in `web/public/sounds/<set>/` (`.ogg` and `.mp3`, Move/Capture/Check/Checkmate/Victory/Defeat only), with `web/public/sounds/CREDITS.md`.
   - **Autoplay:** I verify at build time that WebView2 plays the opponent's first move without a click. If it doesn't, `app.py` appends `--autoplay-policy=no-user-gesture-required` to `WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS`, merged with anything the smoke harness already set, and the SR-16 check stays as it is.
10. **Dark mode (FR-1.12):**
    - Mantine's default color-scheme manager uses **localStorage**, so I write a small bridge-backed `colorSchemeManager` (in memory, saved through `set_setting`). The no-browser-storage test keeps guarding this.
    - **No flash:** `app.py` reads the saved scheme, plus the Windows `AppsUseLightTheme` registry value for Match system (`adapters/desktop.py`), and passes `background_color` to `create_window`. It also adds `?scheme=dark|light` to the start URL, so `main.tsx` renders in the right scheme on the first paint.
    - *Match system* uses Mantine `auto` (`prefers-color-scheme`, which WebView2 updates live when the Windows theme changes).
    - The board keeps the brown theme in both schemes.
11. **One settings service:** `services/ui_settings.py` replaces the ad-hoc keys in `MixerService`. Allowed keys, each with a validator:
    - `mixer.filters`
    - `ui.color_scheme` (`light` / `dark` / `auto`)
    - `ui.sounds` (`{on, volume 0–100, set}`)
    - `ui.coordinates`
    - `puzzle_db.auto_check`

    `get_settings` returns a typed `UiSettings` DTO with all of them. The new defaults in `FilterSpec` are `min_popularity=50`, `min_plays=100` and `exclude_solved_here=True`. Filters saved by v0.1 have those fields stored as `null` / `false`, so the first time v0.2 loads them it applies the new defaults once, tracked by a `mixer.filters_version` marker. After that, whatever you set is kept.
12. **Update check (FR-2.5):**
    - `services/db_update.py`'s `UpdateCheckService(http, clock, settings, read_meta)` runs as a job shortly after launch. It never blocks, and offline it fails silently with only a log line. It fetches `sha256sums.txt`, a `HEAD` for the file (`Last-Modified`, `Content-Length`) and the database.lichess.org page for an approximate count (parsed best-effort; the line is left out if it can't be read).
    - **Newer** means the published hash differs from `meta.sha256`, or, when `meta` has no hash, `Last-Modified` is later than `export_date`.
    - **Limits:** at most one automatic check a day (`Clock`; the last check is stored in `settings`). The automatic check can be turned off, and a **Check for updates** button in the update dialog forces a check.
    - **Banner** (non-blocking, above the main area, never a modal): *Update now* starts the existing import, *Not now* hides it until the next launch, and *Skip this export* stores the skipped hash.
    - **Exact counts:** `PuzzleDbWriter.finish()` attaches the old DB and counts new and removed IDs before the swap. The job's final message is *"6,201,004 puzzles: 44,112 new, 450 removed."*
13. **Icon and shortcuts (NFR-8a):**
    - `assets/icon/weaksquare.svg`: a 2×2 board in the board's light and dark colors, with the cburnett black queen (GPL-2.0+) taken from chessground's assets.
    - `scripts/make_icon.py` renders it with Playwright at 16, 20, 24, 32, 40, 48, 64, 128 and 256 px and packs a PNG-entry `.ico` with the stdlib. The script is deterministic, and the `.ico` is committed.
    - **Window and taskbar:** pywebview's `icon` argument only works on GTK/Qt, so on Windows `adapters/desktop.py` sets an explicit AppUserModelID (`SetCurrentProcessExplicitAppUserModelID`) before the window is created. After it's shown, it sends `WM_SETICON` (big and small) with `LoadImageW`. That way the taskbar shows the WeakSquare icon instead of Python's, which I verify on the real app.
    - **setup.py:** `create_shortcuts()` makes the Start-menu and Desktop shortcuts with `IconLocation`. The Desktop path comes from `SHGetKnownFolderPath(FOLDERID_Desktop)` through ctypes (OneDrive-redirected desktops work). `--no-desktop-shortcut` and `--no-shortcut` skip them. Saving the same `.lnk` path overwrites it, so a re-run never duplicates.
14. **Keyboard shortcuts:**
    - **N** or **Enter** for Next/Skip, **H** for Hint, **A** for Show answer, **←/→** to step through the answer, **C** for coordinates, **?** for a shortcut list.
    - They're ignored while focus is in a text field, and each key is a no-op unless its button is enabled.
    - **Auto-orient** already shipped in v0.1 (the board faces the player's color), so v0.2 only adds a test for it. The **coordinates toggle** is saved through the bridge.
15. **Importer wording (FR-2.1a):** the ImportView, the User Guide and `setup.py`'s help text all say it's the **entire** Lichess puzzle database: about 300 MB compressed, about 6 million puzzles, about 1.5 GB once imported.

## Notes from the build (deviations; recorded in ARCHITECTURE.md §7)
- Ratios use **quota allocation** (`core.queue.allocate`, largest remainder over the whole session) instead of a weighted pick per slot (`pick_bucket` in decision 4). A 50/30/20 mix stays within one puzzle of exact, even in a 15-puzzle session.
- The `puzzle_rating` backfill runs when Stats is read, not at startup: running it in `build_services` kept a connection open on the main thread, which blocked a puzzles.db swap from a second `Services` in the tests.
- *Only my misses* wins over *Exclude solved here*: a puzzle you won once and missed since counts as a miss.
- The filter panel scrolls on its own (`ScrollArea`, viewport height): when it grew taller than the window, the page scrolled and the fixed header covered the top of the board. The e2e click helper also scrolls the board into view.
- The mixer recounts after every recorded attempt (`historyVersion`), because Exclude solved (on by default) changes the count as you play. Found by the new e2e tests.
- Choosing the preset that's already selected reloads it (`onOptionSubmit`, `allowDeselect={false}`).
- B15 was already fixed in the User Guide's Rating row before v0.2 started.
- `services/ui_settings.py` landed in step B (not C), because the coordinates toggle needed it. Step C adds the color-scheme, sounds and update-check keys to it. The coordinates toggle lives in the ☰ menu and on C until the Settings modal arrives in step C.
- The Hint and Show answer buttons are inline in `TrainerView` rather than a separate `HelpControls` component.
- Dark mode: no `?scheme=` start URL. `main.tsx` waits for the saved scheme before the first render, and the window background is painted in it.
- The Light/Dark test checks WCAG AA on every visible text node. Mantine's defaults failed it, already in v0.1's light theme, so the theme overrides five colors (see §7).
- Sounds: `.ogg` only (Chromium plays it). lila's `Checkmate.ogg` is a symlink to `Check.ogg`, so each set ships a copy. The autoplay switch wasn't needed (a smoke test proves audio plays without a click).
- The smoke harness stops with the build command when `web/dist` is stale. QA's v0.1 real-app flow now unticks Exclude solved to replay its solved puzzle.
- The update check is started by the front end once per launch (not by `app.py`), so its result can't arrive before the UI listens. After an update import the dialog stays open to show the exact new/removed numbers.
- The update-check fixtures needed scrubbing: Lichess's page has a sample CSV with real game URLs. `test_fixtures_clean.py` only scanned five extensions and missed the `.html`; it now scans every text file.
- The filter panel is sticky, so the update banner doesn't push Start or the board out of view.
- `setup.py` wasn't run for real during the build (it would write to Adam's actual desktop and Start menu). Its shortcut code is tested with a fake shell call, and the known-folder lookup was checked: it returns the OneDrive Desktop on this PC.
