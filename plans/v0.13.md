## What exploration found (these shape the design)
- **The book is thinner than FR-12 assumes.** It has 3,865 lines, not about 3,500. The median is 5 full moves; only 54 lines reach 12 moves and 1 reaches 16. It has no main-line marker either, and `uci` and `epd` exist only in the generated `dist/` output, so we compute them. FR-12.1 and 12.7a get reworded.
- **`repertoire_nodes` can't be both a tree and reuse transpositions.** `parent_id` allows one parent, but a reused position can have several. Moves become edges keyed by position, and `parent_id` goes. "Removing" a line deletes moves no longer reachable from the root.
- **FENs must be normalised.** Move counters differ across transpositions, so the key is `board.epd(en_passant="legal")`, the same rule the dataset uses.
- **`core/srs.schedule` doesn't fit as it stands.** It returns no card until a first miss, but repertoire positions must be scheduled from first sight. It gets a new function using the same intervals.
- **The per-run cap isn't really per run.** `LlmUsageService.quote` checks one request at a time, so a many-request prefetch would pass it. It needs a batch quote, plus a cumulative check during the job.
- **"Recent average response time" has no data.** `llm_usage` has no duration column, so the migration adds a nullable one.
- **FR-12.3 needs a carve-out.** The interactive engine suits what you're looking at, but prefetch and the builder are bulk jobs and would starve it. They use `analyse_background`, the Game Review pattern.
- **`LlmUsageService.run` holds its lock across the network call.** Prefetch sends one request at a time, so a puzzle Explain may wait for at most one request. I'll accept this and not change the lock.
- **Wikibooks can be fetched cleanly.** `action=query&prop=extracts|revisions&explaintext=1` returned plain text and revision data in my test, and a missing page returns `missing: true` with HTTP 200. Quality varies: main openings 350-900 words, a deep line 52 words.
- **Wikibooks text is publicly editable, so it's untrusted input to the LLM.** Prompt tests must cover instructions planted in the text.
- **Wikibooks fixtures can't be real text without attribution in a public repo.** Fixtures use invented text in the API's shape.

## Licence handling for AI notes based on Wikibooks (CC BY-SA 4.0)
This is the question left open in brainstorming. I'm taking the cautious route, which works whichever way it's answered. It isn't legal advice, so tell me if you'd like to get one.
- The app **doesn't ship** Wikibooks text. It's fetched at runtime and stored locally.
- Each note records the pages and revisions it used. It shows "Based in part on Wikibooks: *page*, CC BY-SA 4.0, may be adapted", with app-built links to the page and licence.
- **Exported notes** carry the same notice and are marked CC BY-SA 4.0.
- Fixtures and the starter data contain no Wikibooks text.

## Design

### Lines (FR-12.1, 12.2, new 12.13)
- Bundle the pinned TSVs (CC0) under `src/weaksquare/opening_book/`, with a commit and SHA-256 pin. Import them with validation on first opening the screen, as a job, and again only when the bundled version changes.
- **Ranking:** explorer popularity when available; otherwise the number of book lines under a move, then fewer moves, then name. The main line follows the top-ranked move at each step, and sub-lines are the next-ranked branches.
- **Extending:** after the book ends, continue with the explorer's most-played move, otherwise Stockfish's best. Every move shows its source. With *Stop at the book's end*, preset lengths are upper limits and the dialog shows the real counts.
- **Explorer:** new `adapters/lichess_explorer.py`, one request at a time, handles 429s, cached 30 days. Settings for source and ratings (default Lichess, 1600-2000, blitz and slower). Signed out or offline, it's skipped cleanly.

### Repertoire (FR-12.4, new 12.14)
- **Build my repertoire** is a background job. It takes a color, an opening and limits (default 12 moves, replies with at least 5% of games, up to 3 replies per position, up to 60 positions). All limits are editable, and the screen shows what the run will request.
- **Your answer at each position,** in order: one you already have → book → the explorer's most-played if within 50 cp of the engine's best → engine best.
- **Gaps flagged:** an answer that fell back to the engine, too few games, or a bad eval.
- You **review the tree before anything is saved**. It never overwrites a move you already stored.
- `source` gains `explorer`, with no CHECK constraint, so v0.14's `study` needs no table rebuild.

### Learn (FR-12.5-12.8, new 12.15, 12.16)
- One screen, reusing `Board`, `EnginePanel` and the analysis state. A switch chooses step-through or play-along. Play-along gives a retry and a nudge, with no scoring.
- The tree and line screen also has "What if they play…?" (FR-12.8).
- **Notes:** new request kinds `opening_overview`, `opening_line`, `opening_move` under a new **Openings** feature in the per-feature model setting (FR-1.15). They follow the `GameExplainService` pattern and reuse `clean_text` and `parse_annotation`.
- **Wikibooks in the prompt:**
  - Pages are looked up by the line's SAN path, with a size limit per page and per request. URLs and the reference sections are stripped.
  - It's marked as untrusted reference text, and **the engine outranks it** when they disagree.
  - No Wikibooks request is made before Confirm, so unfetched pages count at the size limit and the estimate runs high.
  - A missing page, an offline run or the setting turned off means engine-only grounding, and the note says so.
- **Wikibooks panel (my addition, veto below):** the same text shown as its own attributed panel, so you get concepts with no AI key.
- **Cache:** `opening_notes` as in FR-12.7. A page edit doesn't re-bill you; Regenerate uses the latest text.
- **Prefetch dialog:** FR-12.7a and 12.7b in full, using a new `quote_batch`. Split-into-runs groups lines greedily under the cap. Cancel keeps finished notes.

### Practice and stats (FR-12.9-12.11)
- The app walks from the root to due positions, playing stored opponent replies weighted by main line and popularity. New `opening_attempts` table, so puzzle stats, ratings, Coach and sync can't be affected.
- Mistake reasons use `source = 'opening'`. A Stats tab in the Openings page covers FR-12.11.

## Verification
Everything in ROADMAP's v0.13 *Done when* list, plus these new tests:
- The bundled file matches its pin, all 3,865 lines validate, and transpositions share a key.
- **No LLM moves:** an LLM answer naming a new move never reaches the board or the repertoire. This includes Wikibooks-grounded notes and Build my repertoire.
- **Wikibooks:**
  - A page with planted instructions changes nothing that's drawn or stored.
  - A missing page and offline both fall back to engine-only grounding.
  - URLs never reach the prompt or a link.
  - Every note using a page shows its attribution, and exports carry it.
  - No fixture holds real Wikibooks text.
- **Extension setting:** each setting gives the right lines and counts, signed in and signed out, and every move shows its source.
- **Run cap:** `quote_batch` blocks a run whose single requests each pass. A run stops at the cap and keeps finished notes.
- **Repertoire:** removing a line keeps a position another line still reaches.
- **Builder:** nothing is saved before review, your stored moves stay, and gaps are flagged in fixture cases.
- **Isolation:** opening attempts leave puzzle stats, ratings, sync and Coach unchanged.
- Self-check commands, `check_docs.py --strict`, and a Playwright flow through browse, learn in both modes, prefetch, build, practice and tooltips.
