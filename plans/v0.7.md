# v0.7 plan: LLM Explain + cost guardrails

## Context
v0.6 was signed off and merged on 2026-11-03, and the v0.11 coaching plan is on `main`. v0.7 adds the optional AI layer (ROADMAP v0.7):
- **Provider setup:** Anthropic or OpenAI, a model, an API key in Credential Manager, and **Test key** (FR-1.2–1.4, 1.6).
- **All cost guardrails first**, before the first real LLM call can happen:
  - the price table and the usage log
  - estimates, the per-run cap and the monthly budget
  - `max_tokens` on every request and the reasoning setting
  - the spend indicator (§9.3, FR-1.10)
- **Explain**, step 3 of the stuck ladder (FR-8.1–8.8). It's built on grounded context and returns structured JSON. Every move and square is validated, the explanation is drawn on the board with **Show me**, and results are cached.

Work happens on branch `v0.7` from `main` (check the branch first, per memory). This plan is saved as `plans/v0.7.md` in the first commit and ticked off as items land.

**Requirement IDs in scope:** FR-1.2–1.4, FR-1.6 (the LLM half of the fast path), FR-1.8 (the LLM settings in the gear), FR-1.10, FR-8.1–8.15, SR-1, SR-5, SR-7, SR-10, SR-11. The `llm_prices`, `llm_usage` and `llm_cache` tables are from §4.3.

**Out of scope (later versions):**
- Game Review AI (v0.9). Coach, Coach estimates with Confirm, and Coach `max_tokens` (v0.10/v0.11). The guardrail service is written for any feature, but only `explain` calls it in v0.7.
- The FR-8.16 game-text rules: v0.7 sends no game text.
- Sanitized markdown: LLM text is rendered as plain escaped text, with no markdown library.

## Decisions from Adam (planning, 2026-11-03). REQUIREMENTS.md and ROADMAP.md change in the first commit to match
1. **Models: you choose, nothing is pre-selected.** The model field is a dropdown of every model in the price table for the chosen provider, each showing its rough cost per Explain. You can also type any other model ID.
   - Until you pick a model, Test key checks only the key, and Explain says *Pick a model in Settings*.
   - FR-1.3 ("pre-filled with a default") and §2's "to decide: default model IDs" are reworded.
2. **The monthly budget blocks at 100%.** It warns at 80%. Requests go through until this month's logged spend reaches the budget, so the last request can take you slightly over. The **per-run cap** is still checked before each request, against its worst-case cost (FR-8.12).
3. **Explain requires Stockfish.** Without it, the Explain button is disabled and the existing install banner shows.
4. **Explain works in Danger spotting.** The context also includes the highlighted candidate, your call and the truth about it, so the explanation covers why that move was safe or was the blunder.

**My defaults (say if you want otherwise):**
- **When Explain is available:** once the puzzle is over (the line is complete or Show answer was used), the same gate as the engine (FR-7.3).
  - The ladder already makes Explain come after Show answer, and Show answer is a loss, so Explain never decides an attempt. `help_used = 'explain'` is never written in v0.7. FR-5.2 stays true, and §7.2 says so.
  - Practice runs can use Explain too. It explains the moves of the current run.
- **A model that isn't in the price table can't be used** until you add its prices, because every cost has to come from the table (FR-8.9). Test key still works for it, since the key check is free.
- **Reasoning setting:** *Low* (the default), *Medium* or *High*.
  - Anthropic gets `output_config.effort`, which every current Claude model accepts. There's no "Off", because Opus 5.5 and others refuse `thinking: disabled`.
  - OpenAI gets `reasoning.effort`.
  - Medium and High raise Explain's `max_tokens` to 2× and 4× of 1,500, so thinking can't cut the JSON short. The estimate and the cap use the raised limit (FR-8.15).
- **The estimate:** input tokens ≈ prompt characters ÷ 3 (deliberately high). Output is shown as typical (≈ 600 tokens) next to the worst case (`max_tokens`). The cap is checked against the worst case. The Explain button shows "≈ $0.001" inline, with no confirm (FR-8.11).
- **Cache hits are free and always allowed**, even over the budget. They're keyed by `(puzzle_id, move path, provider, model)` as in FR-8.6. The reasoning level isn't part of the key.
- **Test key costs nothing.** It calls `GET /v1/models/{model}` (or `/v1/models` when no model is picked) on either provider. The FR-1.6 silent test at launch uses the same free call.
- **No automatic retry of the generation request** (`retry=False`), so a timeout can never be billed twice. Errors are marked retryable, and you click again.
- **No SDKs.** Both providers are called with raw JSON through `adapters/http.py` (CLAUDE.md: every external call goes through it). `http.py` gains a per-request `headers=` argument for Anthropic's `x-api-key` and `anthropic-version` headers.

## Design (each item gets an ARCHITECTURE §7 entry)

### 1. Storage: migration `user/0006_llm.sql` (new tables only)
- `llm_prices(provider, model, input_per_m, output_per_m, long_ctx_threshold, long_input_per_m, long_output_per_m, as_of, PRIMARY KEY(provider, model))`
- `llm_usage(id PK, ts, feature, provider, model, input_tokens, output_tokens, cost_usd, status)`. `status` is ok / truncated / refused. A row is written for every response that reports usage.
- `llm_cache(key PK, provider, model, response_json, input_tokens, output_tokens, created_at)`, as in §4.3. The key is a SHA-256 of the canonical `(puzzle_id, move path, provider, model)`.
- **Seeding:** the §16 prices are inserted from the provider-defaults module, not from SQL, so model names live in one place (CLAUDE.md). This happens on startup when the `llm.prices_seed` setting is below the module's `SEED_VERSION`. It only adds rows that are missing. A row you edited or deleted isn't touched again until a new seed version.
- `settings` keys:
  - `llm.provider` (`none` / `anthropic` / `openai`)
  - `llm.model.anthropic` and `llm.model.openai` (empty means none picked)
  - `llm.reasoning`
  - `llm.run_cap_usd` (default 0.50) and `llm.monthly_budget_usd` (default 5.00)
  - `llm.prices_seed`

### 2. Core (pure; unit-tested)
- `core/llm/defaults.py`: the **only** module with model names (CLAUDE.md). It holds the seed price rows (§16: the four Claude models, with Haiku 5.5's tier above 100k, and the four GPT models), `SEED_VERSION`, the `max_tokens` defaults (Explain 1,500) and the reasoning multipliers.
- `core/llm/cost.py`: cost from a price row and token counts, with the long-context tier chosen by input tokens. `estimate(prompt_chars, max_tokens, price)` returns the typical and worst-case cost.
- `core/llm/guardrails.py`: `check(worst_case, run_cap, month_spent, budget)` returns ok, `over_cap` or `over_budget`. There's also the 80% warning level, and the month window from an injected `now` (local calendar month).
- `core/llm/provider.py`: the `LLMProvider` protocol (`test_key(key, model)`, `generate(key, request) -> LLMResponse`). It also has the `LLMRequest` and `LLMResponse` types, with usage and the stop status, and `LLMError` kinds: `bad_key`, `quota`, `rate_limited`, `network`, `timeout`, `refused`, `truncated`, `bad_model`, `server`.
- `core/explain.py`:
  - **Context builder:** an allowlist of fields only (SR-11). It takes the FEN before and after the opponent's move, the side to move, the solution in SAN and UCI, the themes, your moves, the refutation of your wrong move, the MultiPV top 3 lines and evals "for you", and the python-chess attack/defense facts for the key squares. For each solution move, the facts are what it attacks and what defends it.
  - Danger spotting adds the candidate, your call and whether it was safe.
  - No puzzle ID, rating, username or settings is sent.
  - **Prompt:** use only the moves given, never invent pieces or moves.
  - **Schema:** `{summary, steps[{ply, text, annotations[{type: arrow|circle, from?, to?, square?, color}]}], key_ideas[]}`.
  - **Validation (FR-8.4):**
    - Parse defensively, even with structured outputs.
    - Steps map onto the solution by `ply` index, and steps for plies that don't exist are dropped. Every move is replayed legally from the puzzle position.
    - Squares must be `a1`–`h8`, colors must come from {green, red, blue, yellow}, and text is capped in length.
    - Each dropped item is counted, and the result carries `discarded > 0` for the note.

### 3. Adapters
- `adapters/llm/anthropic.py`: `POST https://api.anthropic.com/v1/messages` with `x-api-key` and `anthropic-version`. The request sets `max_tokens` and `output_config: {format: {type: json_schema, schema}, effort}`. It reads `usage.input_tokens` and `usage.output_tokens` and the `stop_reason` (`max_tokens` → truncated, `refusal` → refused). `test_key` is `GET /v1/models/{id}`.
- `adapters/llm/openai.py`: `POST https://api.openai.com/v1/responses` with a Bearer key, `max_output_tokens`, `reasoning.effort` and `text.format` json_schema (strict). It reads `usage.input_tokens` and `usage.output_tokens` (reasoning tokens are included in output) and the `status`/`incomplete_details`. `test_key` is `GET /v1/models/{id}`.
  - **The exact request and response shapes are checked against OpenAI's API reference when this file is written.** The fixture is hand-written from the docs and marked as such until Adam's live run records a real one, as the Lichess fixtures were (v0.3).
- `adapters/http.py`: an optional `headers=` argument on `request_json`/`post_json`/`get_json`. Errors never carry headers (as today).
- `adapters/logging_setup.py`: also redacts `x-api-key: …` and `"api_key"`/`"x-api-key"` JSON fields. The `sk-…` pattern is already covered.
- `adapters/secret_store.py`: new account names `anthropic` and `openai`, one key per provider in the same per-data-folder service. Nothing else changes, and it's still the only keyring importer.
- `tests/fakes/llm.py`: `FakeLLMProvider`. It's scriptable: canned JSON, usage, errors, and invalid moves and squares for the validation tests.

### 4. Services
- `services/llm_settings.py`: provider/model/reasoning/cap/budget get and set (validated), key set/delete through `secret_store` (the key is never returned; only *key stored: yes/no*), price table CRUD (validated numbers, provider in the known set), the seed step, and Test key as a job.
- `services/llm_usage.py` (the guardrail service, shared later by Game Review and the Coach):
  - `quote(feature, provider, model, prompt_chars, max_tokens)` returns the estimate and the guardrail verdict.
  - `record(response)` writes `llm_usage` with the cost from `llm_prices`.
  - `month_spend()` gives the spend indicator.
  - Every provider call goes through `run(feature, request)`, which checks the cap and budget, calls the provider and records the usage. That guarantees no unlogged or unchecked call, and a test asserts it.
- `services/explain.py`:
  - **Inputs:** the puzzle state from `SessionService` (finished only, else `ConflictError`). The engine data comes from the interactive engine: it reuses `cur.analyses` and `cur.refutation` when they're cached, and otherwise runs the same `analyze`/`get_refutation` paths, which already validate input (FR-7.6).
  - **Gates and run:** Stockfish must be installed (`EngineNotInstalled` otherwise). Explain checks the cache first, then quotes; a cap or budget block is an `AppError` with a clear message. Then it runs as a job (decision 7) and validates the result before caching it.
  - **Errors (FR-8.8):** readable messages for each `LLMError` kind, with a 60 s request timeout.
- `services/account.py` (the FR-1.6 launch check): the fast path also needs the configured LLM key to pass the free silent test. If it fails, the full form opens with *Your AI key didn't work: <reason>*.

### 5. Bridge (allowlist test updated in the same commit; `gen_types.py`)
New `@bridge_call` methods:
- **Settings:** `get_llm_settings`, `set_llm_settings(provider, model, reasoning, run_cap_usd, monthly_budget_usd)`.
- **Key:** `set_llm_key(provider, key)` (the key arrives from the masked field, goes straight to `secret_store` and is never logged; `bridge_call` logs only the method name) and `delete_llm_key(provider)`.
- **Test key:** `start_llm_key_test(provider, model)` returns a job ID.
- **Prices:** `list_llm_prices`, `save_llm_price(...)`, `delete_llm_price(provider, model)`.
- **Spend and Explain:** `get_llm_spend`, `get_explain_quote(session_id)` (cost, verdict, cached flag) and `start_explain(session_id)` (a job ID; the result arrives through `get_job` as an `ExplainDTO`).

No DTO ever carries a key.

### 6. Front end
- **Startup page:** under the account panel, an **AI explanations (optional)** block. It holds the provider select (None / Anthropic / OpenAI), the model dropdown (from the price table, with ≈ cost per Explain, nothing pre-selected, typing allowed), a masked key field with **Save key** / **Remove key**, and **Test key**, which shows the result. The fast path hides this block until you click *Show all options*.
- **Gear settings → AI:** the same controls, plus reasoning (Low/Medium/High), the per-run cap, the monthly budget, this month's spend, and an editable **price table** (Mantine table: add, edit and delete rows, with *as of* shown).
- **Spend indicator** in the header whenever a provider is configured: "AI $0.03 / $5.00". It turns yellow at 80% and red at 100%, and clicking it opens the AI settings.
- **Trainer:** an **Explain (≈ $0.001)** button after Show answer in the ladder, shown only when a provider and key are configured. It's enabled once the puzzle is over and Stockfish is installed. Its tooltip gives the reason when it's disabled (over the budget, over the cap, no model, no price row, no engine). A cache hit reads *Explain (saved)*.
- **Explanation panel:** the summary, key-idea chips, one step per solution move, the *some annotations were discarded* note, and the model and actual cost. **Show me** steps through the solution (← / →) and draws each step's arrows and circles. It reuses `AnswerPlayer`, and `Board` gets a `shapes` prop next to the hint circle. All text is plain React text, never `dangerouslySetInnerHTML`.
- **Mock client:** all the new methods with fixed data (including a discarded annotation and an over-budget state), for e2e and screenshots.
