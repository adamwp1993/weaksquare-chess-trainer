## Decisions from Adam (2026-11-09, v0.16 planning)
| Question | Answer |
|---|---|
| How Restore swaps in the data | **The app restarts** (Adam). The backup is checked and staged as `user.restore.db`; the app closes and reopens itself, and the swap happens at startup before anything opens the database. About 30 services keep in-memory state, so an in-place swap was rejected. |
| Undoing a restore | Your current data is saved aside as a normal **backup `.zip`** in `<data>\backups\` (`before-restore-<stamp>.zip`, last 5 kept), so **Restore from a backup** can undo a restore directly. |
| Settings that stay with this PC | The Stockfish location isn't stored in `user.db` (it comes from `<data>\engines\`), so no migration. A restore keeps this install's values for `backup.*` (the automatic-backup folder is a path on this PC), `puzzle_db.last_check` / `puzzle_db.skipped_export` (this PC's `puzzles.db`), `lichess.account` / `lichess.scopes` (the sign-in in this PC's Credential Manager), and `debug.time_offset_days`. *Build:* also `engine.custom_path` / `engine.custom_name` (an `.exe` on one PC) and `engine.threads` / `engine.hash_mb` (sized to its hardware); `engine.think_s` travels. |
| Restore while background jobs run | Refused with a message naming them (*"Wait for the analysis to finish, or cancel it"*). |

## v0.16a: backend (stdlib `zipfile` and `sqlite3`, no new dependency, no migration)
- [x] `core/backup.py` (no I/O): manifest (`format: "weaksquare-backup"`, `format_version: 1`, app version, schema version, `created_at` from the Clock, counts: games, puzzle attempts, Coach reports, and the SHA-256 of `user.db`), parsed and checked here. Retention (which old automatic backups to delete), the due check, and `PC_LOCAL_KEYS`.
- [x] `adapters/backup_files.py`: snapshot with the SQLite backup API into a temp file, then `integrity_check` and a schema read on the copy. The zip is written to a temp name next to the target and `os.replace`d, so a half-written file never appears under the real name. Reading a backup opens only `manifest.json` and `user.db` (never `extractall`), checks the size against free disk space before extracting, and verifies the CRC and SHA-256.
- [x] `services/backup.py`:
  - Back up now as a background job (`kind="backup"`) with progress.
  - Inspect: what's in a backup, or refused as *not a backup*, *damaged*, or *newer version* (the NFR-3 message).
  - Stage restore: inspect, refuse while jobs run, write `user.restore.db` with this PC's settings carried in, request a restart.
  - Automatic backups: checked at startup and then by `TimerScheduler` (re-checked hourly, so sleep or hibernate can't skip one). Retention deletes only files named `weaksquare-backup-*.zip` with a valid manifest. A missing folder sets `backup.last_error`, shown in Settings, and is retried next time.
- [x] Startup apply in `app.py`, after the lock and before migrations: save the current data as `before-restore-…zip`, swap in `user.restore.db`, delete `user.db-wal` / `user.db-shm`, run the normal migrations. If any step fails, the original data is put back and a message is shown.
- [x] Restart: `--after-restore` launches the new process, which retries the instance lock for up to 15 s while the old one closes. `Desktop` gets Save, Open and Folder dialogs.
- [x] Bridge methods with `@bridge_call` and the allowlist test updated: `backup_now`, `inspect_backup`, `restore_backup`, `get_backup_settings`, `set_backup_settings`, `choose_backup_*`.

**v0.16a landed (2026-11-09):**
- Bridge methods as built: `get_backup_status`, `set_backup_settings`, `choose_backup_folder`, `backup_now` (opens the
  Save dialog itself), `choose_backup_to_restore` (Open dialog, returns what's in it with a one-time token),
  `restore_backup(token)`, `take_restore_notice`. No path ever comes from the page.

  (found by the refusal tests).

- `engine.custom_path` / `custom_name` / `threads` / `hash_mb` added to the PC-only settings (found writing the
  Developer Guide; see Decisions).

## Tests (ROADMAP *Done when*, plus)
- Round trip: back up, restore into an empty data folder, every user table in `sqlite_master` matches row for row (generic, so future tables are covered).
- A backup taken while a thread writes continuously passes `integrity_check`.
- Refused, with `user.db` unchanged byte for byte: a file that isn't a backup, a truncated zip, a changed `user.db` (SHA-256 mismatch), a newer schema, a zip with `../` paths.
- An older-schema backup (fixture built at migration 10) restores and migrates.
- `before-restore-…zip` exists, and restoring it brings the original data back.
- A startup swap that fails partway (fault injected) leaves the original `user.db` in place.
- With placeholder secrets in a fake secret store, the backup file's bytes contain none of them.
- PC-only settings keep this install's values after a restore.
- Automatic backups: due at launch, due while open (fake scheduler and clock), only N kept, a file that isn't WeakSquare's survives retention, a missing folder is reported.
